# Copilot-Assisted Packet Sniffer: Seeing the Network Ethically

## Introduction

The purpose of this project was to create a packet sniffer that demonstrates how network traffic can be captured, examined, and interpreted in an ethical and controlled environment. Packet sniffing is an important cybersecurity concept because network packets contain information about how devices communicate. By examining packets, cybersecurity professionals can learn about protocols such as IP, TCP, UDP, DNS, and HTTP.

For this project, I created a Python packet sniffer using Scapy. The project was developed in Visual Studio Code and tested using traffic generated on my own computer. The packet capture was limited to the local loopback interface and TCP traffic on port 8000. This allowed me to demonstrate packet capture without monitoring traffic belonging to other users or networks.

An important part of the project was making sure that sensitive information was not unnecessarily displayed. The program includes redaction for email addresses, passwords, tokens, API keys, bearer tokens, JWTs, authorization headers, cookies, and other sensitive information. IPv4 addresses are also partially masked before being displayed.

## Project Implementation

The packet sniffer was implemented using Python and the Scapy library. Scapy provides the ability to work with network packets and identify different protocol layers.

The main program is contained in `sniffer.py`. The program includes a `parse_packet()` function that examines packets that have already been captured or loaded from a PCAP file. The parser identifies IPv4 and IPv6 information and checks for TCP, UDP, DNS, and HTTP information.

For IPv4 packets, the program records the source and destination addresses, but the addresses are partially masked. For example, an address such as `192.168.1.25` is displayed as `192.168.1.xxx`. This reduces the amount of identifying network information displayed by the program.

TCP information includes source and destination ports, TCP flags, sequence numbers, and acknowledgment numbers. UDP information includes source and destination ports and packet length.

The program also identifies DNS information. DNS questions and answers are parsed so that the project can demonstrate how domain names and DNS records appear inside packets. The DNS information is processed through the redaction functions before being displayed.

The project also includes basic HTTP parsing. The program looks for visible HTTP request and response headers. Sensitive headers such as Authorization, Cookie, and Set-Cookie are replaced with `[REDACTED]`. The program does not return an HTTP message body.

## Packet Capture and Filtering

The live capture portion of the project uses the macOS loopback interface, `lo0`. This interface allows the project to capture traffic generated by the local computer.

The capture is restricted using a Berkeley Packet Filter. The filter used in this project is:

```text
tcp port 8000
```

The capture is also limited to 25 packets. A local Python test server was used to generate traffic on port 8000. I then accessed the local server through `127.0.0.1` to generate authorized traffic for the packet sniffer.

This setup demonstrates why filtering is important. Instead of capturing all available network traffic, the program focuses on the specific traffic needed for the lab. This reduces unnecessary collection of network information.

## Security and Ethical Controls

Ethical controls were an important part of the project. Packet sniffers can expose sensitive information if they are used without authorization. Network traffic may contain IP addresses, DNS requests, authentication information, cookies, and other private data.

For this reason, the project was designed around authorized traffic. The live capture is limited to the local loopback interface and a specific test-server port. The project does not attempt to monitor other people's traffic or bypass operating-system security controls.

The redaction system provides another layer of protection. Email addresses are replaced with `[REDACTED_EMAIL]`, while passwords, tokens, API keys, bearer tokens, and JWTs are replaced with `[REDACTED]`. Authorization and cookie headers are also redacted.

These controls demonstrate that packet analysis can be performed while reducing unnecessary exposure of sensitive information.

## Testing

Testing was performed using pytest and individual Python commands. The tests were used to verify that the parser could correctly identify packet information and that sensitive information was being redacted.

DNS parsing was tested using an in-memory Scapy packet containing a DNS question and answer. Redaction was also tested using sample email addresses, passwords, tokens, and authorization information.

The complete test suite was executed using:

```bash
./.venv/bin/python -m pytest
```

The tests helped verify that changes to the parser did not break the existing functionality.

## Use of GitHub Copilot

GitHub Copilot was used as a development and learning assistant during this project. I used Copilot to help with Python boilerplate, packet parsing, regular expressions, unit-test ideas, command examples, and documentation structure.

The generated code was reviewed and modified during development. I specifically added and reviewed controls for authorized capture, packet filtering, IP masking, and sensitive-data redaction.

Copilot was not used to create instructions for unauthorized packet capture, bypass operating-system permissions, hide network activity, establish persistence, or monitor other people's traffic.

Using Copilot helped me understand how different packet layers can be accessed with Scapy and how security controls can be incorporated into a network-analysis tool.

## Conclusion

This project demonstrated the basic concepts involved in packet capture and network traffic analysis. Using Python and Scapy, I was able to create a program that identifies common network protocols and extracts useful information from packets.

The project also showed why ethical controls are necessary when working with packet-sniffing tools. Limiting the capture to authorized traffic, using a BPF filter, masking IP addresses, and redacting sensitive information helps reduce privacy and security risks.

Overall, the project provided practical experience with packet analysis, Python programming, testing, security controls, and responsible use of cybersecurity tools.
